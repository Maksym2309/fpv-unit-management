ВЕБ-ЗАСТОСУНОК «WILD HORNETS — Tactical OS»
════════════════════════════════════════════

Повноцінний застосунок у окремій вкладці браузера.
Працює поверх існуючих таблиць — той самий функціонал, що й sidebar-форми,
але з тактичним інтерфейсом за дизайном stitch_wild_hornet_tactical_hub.

Розділи:
  ✈️ Журнал польоту — активні вильоти, статуси бортів, посадка, історія
  📻 Карта частот   — матриця бендів, конфлікти, чужі частоти, зміна VTX
  📡 GPS трекери    — Sinotrack + SIM: додавання, прив'язка, статуси
  📦 Інвентар       — весь інвентар з пошуком і фільтрами (довідково)
  👥 Екіпаж         — створення/редагування/завершення екіпажів
  + Новий виліт     — жовта кнопка зверху сайдбару

ФАЙЛИ:
  WebApp.html — весь застосунок (один файл)
  WebAppBackend.gs — doGet() + діалог з посиланням

ВСТАНОВЛЕННЯ (для КОЖНОЇ з двох таблиць — головної та операторської):
  1. Відкрий таблицю → Розширення → Apps Script
  2. Файли → «+» → HTML → назви WebApp → встав вміст WebApp.html
  3. Файли → «+» → Script → назви WebAppBackend → встав вміст
     WebAppBackend.gs
     ⚠ Назвати скрипт «WebApp» не вийде — Apps Script не дозволяє два
     файли з однією назвою, а ім'я WebApp вже зайняте HTML-файлом
     (саме на нього посилається doGet). Назва .gs-файлу може бути
     будь-якою; можна й просто вставити код у кінець Code.gs.
  4. Deploy → New deployment → ⚙ Web app:
       Execute as:      User accessing the web app
       Who has access:  Anyone with Google account (або свій домен)
     → Deploy → скопіюй URL
  5. (опційно) в onOpen() додай пункт меню:
       .addItem('🌐 Веб-застосунок', 'openWebAppDialog')

ВАЖЛИВО:
  - «Execute as: User accessing» — щоб працювали права (мій/чужий виліт)
    і автор записувався коректно. Кожен користувач при першому відкритті
    підтверджує доступ.
  - Операторській таблиці нічого додатково не треба — OperatorCode.gs
    вже має всі потрібні функції (той самий WebApp.html працює з обома).
  - При оновленні WebApp.html не забудь Deploy → Manage deployments →
    Edit → Version: New version, інакше зміни не з'являться.

ДЕМО-РЕЖИМ:
  Якщо відкрити WebApp.html просто з диска (подвійний клік) — застосунок
  запуститься з тестовими даними (жовтий банер зверху). Зручно щоб
  подивитися інтерфейс без деплою.

СУМІСНІСТЬ ІЗ SIDEBAR:
  Веб-застосунок нічого не змінює в існуючих формах — вони працюють
  як і раніше. Дані спільні: все, що зроблено у застосунку, одразу
  видно в таблиці й формах, і навпаки.

РІВЕНЬ 2 — НЕЗАЛЕЖНИЙ PWA-ДОДАТОК (GitHub Pages + JSON API)
════════════════════════════════════════════

Що це: застосунок живе на GitHub Pages як справжній додаток
(встановлюється на телефон/ПК, працює офлайн-оболонкою), а таблиця —
невидима база даних. Користувачам НЕ потрібні Google-акаунти й доступ
до таблиці — вхід за позивним/паролем з аркуша «Персонал».

ФАЙЛИ:
  ГОЛОВНА_таблиця/ApiEndpoint.gs — doPost JSON API (+ apiUserEmail_)
  docs/                          — PWA: index.html, manifest, sw.js, іконки
  sync-docs.ps1                  — збірка docs/index.html з WebApp.html
  sync-forms.ps1                 — звірка дубльованих sidebar-форм

ВСТАНОВЛЕННЯ:

1. Apps Script ГОЛОВНОЇ таблиці:
   - Онови Код.gs (у ньому Session.getActiveUser().getEmail()
     замінено на apiUserEmail_() — 27 місць)
   - Додай файл ApiEndpoint (вміст ApiEndpoint.gs)
   - В API_ADMIN_CALLSIGNS впиши позивні адміністраторів PWA
   - Онови WebApp (HTML) і WebAppBackend

2. Деплой: Ввести в дію → Керувати введеннями в дію → ✏:
     Execute as:      Me (я)
     Who has access:  Anyone (будь-хто)
     Версія: Нова версія → Ввести в дію
   URL /exec не зміниться.

3. GitHub Pages:
   - Закоміть і запуш docs/ у репозиторій
   - GitHub → Settings → Pages → Source: Deploy from a branch →
     Branch: main, Folder: /docs → Save
   - За хвилину сайт: https://<нік>.github.io/fpv-unit-management/

4. Перший запуск PWA:
   - Відкрий сайт → жовтий банер «Демо-режим» → «підключити базу» →
     встав /exec URL → сторінка перезавантажиться → вхід за позивним
   - Телефон: меню браузера → «Додати на головний екран»
   - ПК Chrome: іконка встановлення в адресному рядку

5. У WebAppBackend.gs заповни PWA_URL адресою GitHub Pages —
   тоді стара сторінка /exec переадресовуватиме на PWA
   (безпека: при «Execute as: Me» відкривати /exec напряму не можна),
   а пункт меню «Веб-застосунок» у таблиці вестиме на PWA.

ПІСЛЯ КОЖНОЇ ЗМІНИ WebApp.html:
   powershell -File sync-docs.ps1   → коміт docs/ → push
   (в Apps Script оновлювати WebApp тепер не обов'язково —
    фронтенд живе на Pages, бекенд у таблиці)

ПІСЛЯ КОЖНОЇ ЗМІНИ SIDEBAR-ФОРМИ:
   powershell -File sync-forms.ps1
   Спільні форми (AppShell, FlightLogForm, FrequencyForm, SinotrackForm)
   копіюються з ГОЛОВНОЇ в ОПЕРАТОРСЬКУ автоматично — правити треба
   лише в ГОЛОВНІЙ. Тактичні форми скрипт не чіпає, а лише перевіряє,
   чи не розійшлась у них логіка з базовою (стилі різні навмисно).
   Ключ -Check нічого не пише і повертає 1 при розходженні —
   зручно перед комітом.

ЯК ЦЕ ПРАЦЮЄ:
   PWA (браузер) → POST {fn, args, token} → /exec (doPost, ApiEndpoint)
   → whitelist функцій → authSession(token) → виклик функції → JSON.
   Без валідного токена виконується ТІЛЬКИ authLogin.
   Адмін-позивний отримує права ADMIN_EMAIL, решта — стабільний
   псевдо-email opId@op.local (авторство «мій/чужий» працює).

СЕСІЇ:
   Токен живе 30 діб і продовжується сам, поки людина користується
   застосунком (ковзне продовження: щойно лишається менше половини
   строку — відлік починається наново). Тобто вхід на пристрої робиться
   один раз. Сесія вмирає від «Вийти» або 30 діб простою.
   Токени лежать у Script Properties таблиці, протухлі прибираються
   при кожному вході. Строк задає AUTH_SESSION_DAYS у Code.gs.

   ⚠ Токен = доступ до даних підрозділу. Спільний або втрачений
   пристрій знеструмлюється кнопкою «Вийти» на самому пристрої або
   зміною пароля особи (старі сесії цим не рвуться — за потреби
   видали ключі auth_* у Script Properties проєкту).

РОЗДІЛ «ІНФОРМАЦІЯ» (документи підрозділу):
   Показує вміст спільної теки Google Drive — теки й файли, з переходом
   углиб і відкриттям файлу прямо в застосунку.

   Налаштування:
   1. Створи теку на Drive під тим же акаунтом, що володіє таблицею.
   2. Відкрий її і візьми ID з адреси:
        https://drive.google.com/drive/folders/<ЦЕ_І_Є_ID>
   3. Впиши його в INFO_ROOT_ID у Code.gs. Порожній INFO_ROOT_ID —
      розділ чесно каже, що сховище не під'єднане.
   4. Кому видно розділ: чекбокс «Інформація» в аркуші «Персонал»
      (або в застосунку: Екіпаж → особовий склад → ✎). Адмін бачить завжди.

   ⚠ Теку НЕ треба робити «доступною за посиланням». Застосунок віддає
   вміст файлу сам, після перевірки права — саме тому доступ і не витікає
   за межі застосунку. Оператори Google-акаунтів не мають, тож рідне
   шарення Drive їх однаково не розмежувало б.

   Обмеження: файл більший за INFO_MAX_FILE_MB (типово 25 МБ) не
   відкривається — Apps Script тримає відповідь у пам'яті. У списку такий
   файл позначається як «завеликий». Великі відео тримай поза цією текою.

   Перегляд просто в застосунку, без скачування: зображення, PDF, текст,
   відео й аудіо відкриваються у вікні поверх розділу. Google-документи
   показуються експортом у PDF. Кнопка «Зберегти» лишається завжди —
   на iOS Safari вбудований показ PDF буває примхливим.
   Чого тут НЕ буде: перемотки відео наперед і поступового підвантаження.
   Apps Script не вміє віддавати бінарні дані (ContentService — лише текст),
   тому файл приходить цілком у тілі відповіді. Це ж і задає стелю розміру.

   Режими як у решті застосунку — «Перегляд» і «Редагування»:
     Перегляд    — заходиш у теку кліком по рядку; у файла кнопки
                   ↗ переглянути і ⬇ завантажити. Нічого не змінюється.
     Редагування — додаються «Нова тека» й «Завантажити файл», а в рядках
                   і тек, і файлів зʼявляються ✎ перейменувати і 🗑 видалити
                   (замість ↗ ⬇ — робота НАД файлом, а не з файлом).

   Завантажити (⬇) можна БУДЬ-ЯКИЙ файл, у тому числі завеликий для
   перегляду: великий іде частинами по 6 МБ зі смужкою прогресу, бо
   цілком він у памʼять Apps Script не вміщається. Раніше такий файл
   позначався «завеликий» і забрати його із застосунку було неможливо.

   Видалення теки — у кошик Google Drive (setTrashed), не назавжди:
   звідти її можна повернути. Кореневу видалити чи перейменувати не
   можна — вона задана INFO_ROOT_ID і є орієнтиром для «хлібних крихт».
   Тека-двійник із таким самим іменем поруч не створюється.
   Файл перейменовується й видаляється так само — і теж у кошик.
   При перейменуванні лишай розширення (.pdf, .zip): за ним застосунок
   розуміє, як показувати файл.

   ⚠ Право «Інформація» дає і перегляд, і завантаження (як «Інвентар»
   дає редагування інвентарю). Окремого рівня «дивитись, але не чіпати»
   поки немає — скажи, якщо потрібен.

ЯК ІДЕ ЗАВАНТАЖЕННЯ (два шляхи):
   Швидкий (основний). Бекенд відкриває resumable-сесію Google Drive і
   віддає браузеру ЛИШЕ її адресу; далі байти летять у Drive напряму,
   повз Apps Script. Без base64 (мінус 33% обсягу), без файлу в пам'яті
   скрипта, з відсотками прогресу. Стеля — 512 МБ.
   Адреса сесії прив'язана до однієї теки й одного файлу, живе недовго
   і доступу на читання Drive не дає. Токен власника браузеру не потрапляє.

   Запасний. Якщо сесію відкрити не вдалося або PUT не пройшов (CORS,
   обрив), застосунок сам відкочується на старий шлях — base64 через
   Apps Script. Там стеля 25 МБ, бо файл цілком лежить у пам'яті скрипта.
   У смужці прогресу тоді видно позначку «(запасний шлях)».

   Якщо великі файли раптом почнуть впиратися в 25 МБ — значить швидкий
   шлях не працює, і треба дивитися саме на нього, а не на стелю.

ДЕ ЛЕЖАТЬ ПАРОЛІ:
   Тільки в ГОЛОВНІЙ таблиці, аркуш «Персонал», колонка F —
   і тільки як сіль+хеш, не відкритим текстом.
   В операторську таблицю паролі НЕ синхронізуються: syncToOperators
   позначає цю колонку як secretCol, тож там вона лишається порожньою,
   а джерелом правди завжди є головна таблиця.
   Сам аркуш «Персонал» прихований для неадмінів (SHEETS_ADMIN_ONLY).
   Пам'ятай: приховування аркуша чи колонки в Google Sheets — це не
   захист від читання, а лише «щоб не муляло очі». Хто має доступ до
   таблиці на читання, той при бажанні побачить будь-яку клітинку.
   Тому доступ до самої ГОЛОВНОЇ таблиці має бути вузьким —
   користувачам PWA він взагалі не потрібен.

ОБМЕЖЕННЯ:
   - Холодний старт Apps Script: перший запит ~2-3 с
   - Push-сповіщень немає (це вже рівень 3 — справжня БД)
   - Хеш пароля — один раунд SHA-256 із сіллю. Від райдужних таблиць
     захищає, від перебору коротких паролів — ні. Не став короткі.
